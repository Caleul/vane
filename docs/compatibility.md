# Runtime compatibility and reproducible packages

The release supports **Node.js >=24.19.0 <25** and **PostgreSQL 16.x**. The tested local patches are Node **24.19.0** and PostgreSQL **16.15**. Testing those patches is evidence for those exact executions; it does not claim that every Node or PostgreSQL patch has already been tested. The release workflow pins Node 24.19.0 and records actual versions; later patches within the engine range require their own validation. Other Node major versions, PostgreSQL majors, CommonJS package loading, SQLite and alternative SQL adapters are outside this release support matrix.

The package is ESM and publishes generated JavaScript with matching declarations. Application dependencies are installed from the normal npm artifact, without repository links, workspaces or private imports. PostgreSQL must be a real 16.x server for integration/conformance; Moto is an explicitly scoped S3 emulator for consumer verification and does not prove production AWS behavior.

`node scripts/release/pack.mjs --out <directory> --manifest <file>` requires a clean identified Git checkout, supported Node version and a reviewed release version. It builds, verifies the API manifest, obtains npm's public file list, validates required/forbidden contents, and stages exactly those files. Stage directories have mode 0755, ordinary files 0644 and the installed CLI 0755 regardless of checkout umask. npm packs the stage with lifecycle scripts disabled to avoid recursive prepack execution. No source checkout modes are changed. `--skip-build` is available only when the coordinator has just built the same clean candidate; manifest verification still runs.

The JSON result identifies actual commit/tree, version, Node/npm versions, package filename, SHA-256, SHA-512 integrity, API manifest digest, canonical file modes and complete package contents. Release consumers must use that same package. A different npm version, platform or toolchain has a different provenance and requires reproduction; identical bytes are never assumed.

`node scripts/release/reproducibility.mjs --out <directory>` clones the same commit twice into empty directories, installs the locked dependencies and builds/packs under umasks 022 and 077. It requires matching package SHA-256 and records both manifests. This checks checkout/mode determinism with the actual build and npm pack; a repeated pack of one already-normalized directory would not prove it. Output directories should be outside the source checkout or explicitly ignored, so the clean-checkout gate remains meaningful.

The artifact includes dist, the public API manifest, license, README, changelog, public flat Markdown guides and the public Sales/Billing example. Raw source, tests, node_modules, historical evidence archives, credentials and previous tarballs are forbidden. Package-surface tests enforce both necessary files and exclusions. Maps may identify source paths for diagnostics; they do not authorize private imports.
