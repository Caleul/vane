# Phase 3 completion gate

Phase 3 turns Semantic Views into executable PostgreSQL queries and creates the
first versioned public contract boundary. Its design is documented in
[`phase-3-design.md`](phase-3-design.md).

## Acceptance matrix

| Gate | PRD traceability | Executable evidence |
| --- | --- | --- |
| Typed View input/output | FR-VIEW-001, FR-VIEW-005 | Semantic compiler plus runtime input validation and output normalization; `test/view.test.ts`, `test/phase-three.test.ts` |
| View-owned query | FR-VIEW-002–004 | PostgreSQL projection, aggregate, validated joins, filter, order and pagination compiler; no independent Query API |
| Terminal query after persistence | FR-VIEW-006 | public Event runner waits for successful owner persistence and then executes its configured terminal View |
| View-only public success | FR-VIEW-007 | `202 { sagaId }` admission and terminal store expose View or safe fail; internal revision never crosses the boundary |
| Public Event contract | FR-HTTP-002, FR-HTTP-008 | Contract IR retains `Owner.Event` while allowing an independent public path |
| Synchronous View contract | FR-HTTP-003 | typed public View request returns normalized result rows |
| Stable safe failure | FR-HTTP-004 | stable code/message/correlation envelope; stack, SQL and credentials are suppressed |
| Terminal SSE | FR-HTTP-005–006 | one `view` or `fail` event and close; no progress/retry/compensation output |
| Deterministic OpenAPI | FR-HTTP-007 | OpenAPI 3.1 generated byte-identically from content-hashed Contract IR |
| Real boundary | integration strategy | PostgreSQL 16 test applies schema, persists an Event, runs its terminal View and verifies direct HTTP/View plus terminal SSE output |

## Phase boundary

Route exposure is an explicit Contract materializer input in phase 3. Phase 5
will resolve ServiceConfiguration profiles into this same input. The included
terminal result store is an in-process implementation of an interface; phase 4
will bind the interface to durable Saga state and orchestration. Neither
boundary changes Event or View semantics.

## Verification

```bash
npm run verify
VANE_TEST_DATABASE_URL=postgresql://user:password@localhost:5432/vane \
  npm run test:integration
```

The unit gate contains 158 tests. The PostgreSQL gate contains 13 tests and
uses PostgreSQL 16.15 for the complete Event → persistence → terminal View →
public contract flow.
